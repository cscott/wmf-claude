- Phabricator, Gerrit, and GitLab MCP servers are registered. Prefer mcp__phabricator__phabricator_get_task to verify Bug: references in commit messages, and mcp__gerrit__get_commit_message to preserve Change-Id when amending Gerrit-pushed commits. Use the mcp__gitlab__* tools to read gitlab.wikimedia.org merge requests, comments, diffs, and files.
- The local wiki runs in this VM, on its own loopback. Start it with `composer serve > "$TMPDIR/serve.log" 2>&1 &` in the core checkout (`$MW_INSTALL_PATH`); `/tmp` is write-only, so keep logs and scratch files in `$TMPDIR`. Then `curl "$MW_SERVER/index.php?title=Special:Version"`. The server can take a few seconds to answer the first time: retry the curl for a while before you read a `000` (connection refused) as a failure. Prefer curl + `/api.php` for HTTP status, redirects, rendered HTML, and API responses. There is no browser MCP here, so you cannot look at a page yourself: say so rather than guess, and ask the engineer when the question is how a page appears. See ~/MEDIAWIKI-TESTING.md for the test harnesses and /wmf-claude:manual-test for the parts of the ladder that apply.
- Each repo here is your own clone, at the same path as the engineer's checkout. The remote `local` is the engineer's checkout: read-only, and current as of their last fetch. `git fetch local` (or `git safe-reset local`) picks up what they fetched; `origin` is the real upstream. Commit your work on a branch: the engineer fetches it from this VM, and an uncommitted change does not leave the VM.
