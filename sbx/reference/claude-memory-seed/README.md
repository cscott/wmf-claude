# Claude memory seed

A snapshot of this Claude instance's persistent memory files
(`~/.claude/projects/<key>/memory/`) as of **2026-09-14** (two files added from `sbx-translate` 2026-09-18), committed here as
a stopgap because that directory lives on each `sbx` sandbox's own private
overlay disk and does not survive sandbox recreation (see
`sbx/DESIGN-memory-persistence.md` — automatic seed/extract across
sandboxes is designed but not yet built).

## Restoring into a fresh sandbox

Inside the new sandbox, with `~/Projects/Wikimedia/wmf-claude` mounted:

```bash
mkdir -p ~/.claude/projects/-home-cananian-Projects-Wikimedia-wmf-claude/memory
cp ~/Projects/Wikimedia/wmf-claude/sbx/reference/claude-memory-seed/*.md \
   ~/.claude/projects/-home-cananian-Projects-Wikimedia-wmf-claude/memory/
```

The directory-name key is derived from the *host* path of the project
directory, so it is `-home-cananian-...`, not `-home-agent-...`. Check it
against whatever `~/.claude/projects/` already contains before copying, and
copy `README.md` too — it is harmless there and marks the directory as
seeded. `MEMORY.md` is the index Claude loads each session; the other files
are one fact each. See `sbx/NOTES.md` §0.

## Refreshing this snapshot

From inside a sandbox whose Claude has learned something worth keeping:

```bash
cp ~/.claude/projects/-home-cananian-Projects-Wikimedia-wmf-claude/memory/*.md \
   ~/Projects/Wikimedia/wmf-claude/sbx/reference/claude-memory-seed/
```

then restore this `README.md` (the copy above will clobber it with the
seeded duplicate), update the date at the top, and commit.

## Caveat

These files were generated by Claude, not hand-written, and contain
cananian-specific workflow details (email, directory layout, habits) that
are fine for this pre-upstream `sbx/` design work but should be reviewed
before anything under `sbx/` is prepared for wider WMF distribution.
