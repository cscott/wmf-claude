When a question is about **what's inside the sandbox image** (installed
packages, versions, `apt-cache policy`, loaded PHP extensions, what's on
`PATH`), run it here. I already am a sandbox generated by
`wmf-sbx-create`. Don't hand cananian a "verify on the host" command for
it.

**Why:** I wrote "Verify `wmf-sbx exec NAME node --version`" into a design
doc as a blocker, and cananian pointed out I could just test it — node
22.22.1 was sitting at `/usr/bin/node` the whole time. It cost a
round-trip and left a design "blocked" that wasn't.

**How to apply:** split the question first. *Image contents* → test
locally, immediately. *Sandbox lifecycle* (`sbx create`/`rm`/`ports`/
`policy`, mount semantics, host port behaviour) → genuinely needs the
host, because there's no `sbx` binary in here (see [[project-wmf-claude-sbx-redesign]],
sbx/NOTES.md #8). Network *reachability* is a middle case: I can curl an
allowed domain myself; only the policy table needs `wmf-sbx policy ls`.

Related: [[feedback-verify-security-by-bypass]] — same instinct, test
rather than assert.
